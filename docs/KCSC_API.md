# KCSC OpenAPI — 실측 사실과 함정

> 새로 붙이는 사람이 며칠 잡아먹는 것들입니다. 여기 다 적어 둡니다.
> 마지막 실측: **2026-08-05**

## 엔드포인트

```
GET https://kcsc.re.kr/OpenApi/CodeList?key={KEY}                  카탈로그
GET https://kcsc.re.kr/OpenApi/CodeViewer/{Type}/{Code}?key={KEY}  본문
```

- `Type`·`Code` 는 **경로 파라미터**, `key` 는 **소문자 쿼리**입니다.
  (웹검색으로 나오는 요약은 이 형태가 틀린 경우가 많습니다 — 실측이 맞습니다)
- `Code` 는 공백 없는 **6자리 또는 8자리**. `KDS 14 31 10` → `143110`.

## 응답 구조

### `CodeList` — 3,572건

```json
{"no":4240, "codeType":"KDS", "code":"100000", "fullCode":"10101000",
 "name":"공통설계기준", "version":"2021", "updateDate":"2023-03-08T16:27:00",
 "list":null, "listParentCodes":[{"codeType":"KDS","fullCode":"10","name":"설계기준"}, ...],
 "message":null}
```

- **`list` 는 카탈로그에서 항상 `null`** 입니다. 본문은 `CodeViewer` 에서만 옵니다.
- `listParentCodes` = 상위 분류 계층. 검색어 매칭과 맥락 표시에 씁니다.

### `CodeViewer` — 본문

```json
{"no":.., "codeType":"KDS", "code":"143110", "name":"...", "version":"2024",
 "updateDate":"...", "list":[{"no":..,"sort":1,"title":"...","level":1,
                              "label":"1.","contents":"<p>...</p>"}]}
```

응답이 **길이 1인 배열로 감싸여 올 수 있습니다** — `data[0]` 를 꺼내야 합니다.

## ★가장 중요한 구조 — `title` 은 자기 제목이 아니다

`title` 은 그 항목이 **속한 조항의 제목**이고, 그 조항에 딸린 모든 항목에 똑같이 반복됩니다.

```
label='4.2.1.1.3'  title='4.2.1.1.3 압축판요소의 폭두께비'   ← 조항 머리
label='(1)'        title='4.2.1.1.3 압축판요소의 폭두께비'   ← 그 안의 문단
label='표 4.2-2'   title='4.2.1.1.3 압축판요소의 폭두께비'   ← 그 안의 표
```

그래서 **"4.2.3 절을 읽어라"는 `level` 트리를 타는 게 아니라 `title` 앞머리의 조항번호로
고르면 됩니다.** 훨씬 단순하고 안 깨집니다. (`level` 은 문서 트리 깊이라 1~12까지 갑니다)

`label` 의 종류 (KDS 14 31 10, 2,710항목 기준):

| label | 건수 | 뜻 |
| --- | --- | --- |
| `본문` | 1,559 | 라벨 없는 본문 조각 |
| `(1)` `(2)` … | 418 | 문단 |
| `1.` `4.2.3` … | 266 | **조항 머리** |
| `①` `②` … | ~290 | 항목 |
| `가.` `나.` … | ~90 | 항목 |
| `표 4.2-2` 등 | 소수 | 표·그림 캡션 |

## 🔴함정

| 함정 | 답 |
| --- | --- |
| **인증키가 틀려도 HTTP 200** | 필드가 전부 `null` 인 껍데기 한 건(`[{"no":0,"codeType":null,...}]`)이 옵니다. 오류코드도 `message` 도 없습니다. **그대로 두면 빈 카탈로그가 캐시에 박혀 이후 모든 조회가 조용히 "못 찾음"이 됩니다.** → `_reject_null_sentinel()` 로 막습니다 |
| **6자리 코드 충돌** | `143110` 이 KDS·KCS·SMCS·EXCS·LHCS 5곳에 있습니다. 오류로 막으면 못 쓰고, 조용히 고르면 **다른 기준으로 설계하게 됩니다.** → 국가기준(KDS→KCS) 우선으로 고르되 **고른 사실과 나머지 후보를 반드시 표시** |
| **종류가 9가지** | handoff 에는 KDS/KCS 2종으로 적혀 있었으나 실제로는 기관별 전문시방서까지 9종입니다 (SMCS 853·KCS 769·KDS 561·LHCS 544·EXCS 328·KRCCS 226·KWCS 189·NHCS 76·KRACS 26) |
| **코드가 6자리만이 아님** | 8자리도 있습니다 (LHCS·SMCS·KWCS·EXCS 일부) |
| **표 자리표에 숫자를 쓰면 안 됨** | HTML→마크다운에서 `<table>` 을 `"0"` 같은 숫자로 치환한 뒤 정규식 `(\d+)` 로 되돌리면 **본문의 다른 숫자까지 표로 오인**합니다. `\x00TBL0\x00` 같은 자리표를 씁니다 |
| **수식에 텍스트가 없음** | λr·Fcr 등은 전부 base64 GIF 입니다. `alt` 도 MathML 도 **없습니다**(실측: 한 절 71개 이미지 중 alt 0개). 인증키와 무관합니다 — 키는 접근 권한만 줍니다 |
| **★그런데 이미지는 읽힌다** | 오래 "수식은 못 읽는다"고 여겼으나 틀렸습니다. **텍스트로만 없고 그림으로는 멀쩡합니다.** 식 한 줄도, 6×13px 기호(`J`·`Iyc`)도 또렷합니다. 크기도 작아 절당 27~216 비전토큰뿐입니다 → `kcsc_formula` 가 이미지를 그대로 돌려줍니다. **기억으로 채우는 구조 자체가 없어집니다** |
| 이미지 번호 매기기 | 본문 `〔그림 N〕` 과 돌려주는 이미지의 순서를 맞추려면 **이미지를 표보다 먼저** 치환해야 합니다. 표 안에도 수식 이미지가 들어 있어서(표 4.2-2 는 통째로) 표를 먼저 빼면 번호가 어긋납니다 |
| **표가 깨짐** | `<table>` → 마크다운 표로 보존. 기준의 값은 대부분 표에 있습니다 |
| **표가 둘로 쪼개져 옴** | 긴 표는 같은 캡션(`표 4.1-1`)으로 두 항목에 나뉘어 옵니다. 중복이 아니라 이어지는 부분입니다 — 합치지도, 지우지도 말 것 |
| **umbrella 노드** | `xx0000` 류 상위 분류는 `list` 가 없습니다(본문 없음) |
| **조항번호 중복** | 부록에서 번호가 `1.` 부터 다시 시작하는 기준이 있습니다 (KCS 14 31 10) |
| **제목 검색의 한계** | "강관"은 본문 수십 건에 있으나 기준 *이름*에는 5건뿐 → **본문 grep 이 꼭 필요** |
| **TLS** | 과거 검증 실패 사례가 있었으나 2026-08-05 재확인 시 **정상 검증됩니다**. 그래도 검증을 기본으로 두고, 실패 시 조용히 우회하지 않고 `KCSC_INSECURE=1` 옵트인을 안내합니다 |

## 한 줄 요약

**API 하나로 카탈로그와 본문이 다 나옵니다. 로컬 코퍼스가 필요 없어 완전히 독립적인
패키지가 됩니다.** 데이터를 동봉하지 않으므로 재배포 문제도 피합니다.
